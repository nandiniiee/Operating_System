  (a) size 200000 - represents the total number of blocks in filesystem. mkfs sets it using FSSIZE. The kernel uses sb.size in balloc() in kernel/fs.c to determine the filesystem boundary while searching for free blocks.
  (b) nblocks 199328 - represents the number of data blocks available after we have taken into consideration metadata blocks. mkfs calculates it as FSSIZE-nmeta. The kernel does not directly use sb.nblocks
  (c) ninodes 200 - total number of inodes in filesystem. mkfs sets it using NINODES. The kernel uses sb.ninodes.
  (d) nlog 241- number of blocks reserved for the filesystem log, including the log header block. mkfs sets it to LOGBLOCKS + 1. Kernel doesnt directly use sb.nlog
  (e) logstart 2 - disk block number at which the log begins. mkfs sets it to 2 because block 0 is the boot block and block 1 is the superblock. The kernel uses sb.logstart to initalize the logging system
  (f) inodestart 243 - first disk block containing the inode table. mkfs calculates it as 2 + nlog. The kernel uses it through the IBLOCK
  (g) bmapstart 256 - first disk block containing the block allocation bitmap. mkfs calculates it as 2 + nlog + ninodeblocks. The kernel uses it through the BBLOCK
  (h) refstart 281 -  first disk block containing reference-count information for filesystem blocks. mkfs calculates it as 2 + nlog + ninodeblocks + nbitmap. Used through RBBLOCK
