   (b) Prompt- "I am implementing Assignment 5.2 (Sandbox a Command) in xv6. The requirement is to add an interpose system call that takes a syscall mask and a path, stores the mask for the calling process, and makes the mask inherited by children created using fork. I have already added the syscall_mask field to struct proc, initialized it in allocproc(), and copied it in kfork(). I also added SYS_interpose to the syscall table. Can you explain what remaining changes are needed and where the syscall mask should be checked so that a masked system call is rejected?"
      The given response was "The syscall mask should be checked in the central syscall() dispatcher, before the requested syscall handler is called. For syscall number num, the kernel can test whether the corresponding bit is set using a bitwise AND with (1 << num). If the bit is set, the syscall should be rejected, typically by setting the return value to -1 instead of calling the handler. The interpose system call itself should retrieve the mask using argint(), retrieve the path argument using argstr(), and store the mask in the current process's syscall_mask. Since the assignment only uses "-" as the path in this part, the path does not need to be used yet. Fork inheritance is handled by copying the parent's syscall_mask into the newly allocated child process in kfork()."
      The response was used to understand where syscall filtering should be implemented and why the check belongs in syscall() rather than separately inside every system call.
